
# Mux Documentation Overview & Architecture Review

## Executive Summary

Mux is a developer-first video infrastructure platform that abstracts away the complexity of video encoding, storage, delivery, and analytics. Instead of managing video pipelines yourself, Mux handles ingestion, transcoding, adaptive bitrate streaming, content security, and real-time analytics through a clean REST API. The platform is built by video experts with over a decade of combined experience and is specifically designed for teams embedding video into applications.

---

## Core Architecture & Fundamentals

### Organization & Account Structure

Mux uses a hierarchical structure where an organization is the top-level account container that holds everything: environments, team members, and billing settings. This allows flexibility for teams managing multiple projects or clients, each with independent billing. Within an organization, you can create separate environments (development, staging, production) with environment-specific API tokens.

### Key Concepts: Assets, Playback IDs, and Live Streams

The platform revolves around three core entities:

**Assets**: An asset refers to a piece of media content stored or live streamed through Mux. When you create an asset, Mux downloads the file from a provided URL or accepts it via direct upload, then automatically transcodes it into multiple resolutions and bitrates for adaptive streaming. Assets have a unique ID used for management and one or more playback IDs used for streaming.

**Playback IDs**: A playback ID is what you use to actually stream content to viewers. While asset IDs are used to manage content via api.mux.com, playback IDs are used to stream via stream.mux.com. Each asset can have multiple playback IDs with different policies—for example, a public ID for trailers and a signed ID for full content. This separation is powerful because you can revoke access by removing a playback ID without re-encoding the underlying asset.

**Live Streams**: A live stream represents a live broadcast channel. Unlike assets created from existing files, live streams receive real-time input and deliver it to viewers with low latency.

### API Authentication & Security

Mux API requests must be made from a server, not from client-side code. The API does not support CORS, and exposing your credentials in a browser or mobile app is a security risk. Mux uses HTTP basic auth with your access token to authenticate requests. Every request to the API is authenticated via an Access Token, which includes an ID and secret key. Mux only stores a hash of the secret, not the secret itself—if you lose it, you'll need to create a new Access Token.

When creating an access token, you configure which permissions it has. For most use cases, you'll want Mux Video Read and Write permissions. Tokens are environment-scoped, meaning a development token cannot be used in production.

## Secure Video Playback: Signed URLs & DRM

This is where Mux's architecture becomes particularly elegant for your use case.

### Signed Playback URLs with JWT

Signed playback policies enable playback URLs that require a valid JSON Web Token (JWT) to gain access. The JWT should be signed and generated by your application on a protected server, not on a public client. This is the perfect integration point for your Golang backend's auth context.

Signed URLs protect access to content—they control who can request the video stream. For full content protection (preventing screen recording, for example), you'd combine signed URLs with DRM encryption. Mux supports two playback policies: public and signed. Public playback IDs work without any restrictions—anyone with the URL can watch. Signed playback IDs require a valid JWT.

The workflow is straightforward:

1. Your Golang backend authenticates a user
2. When the user requests video access, your backend generates a JWT containing claims like expiration time and optional user-specific restrictions
3. The JWT is signed with your private key (RSA 2048-bit)
4. The signed JWT is passed to the frontend
5. The Mux Player validates the JWT before streaming
6. If the JWT is invalid or expired, Mux denies access

The JWT is a JSON document signed with a SHA-256 hash calculated using an RSA private key that can be verified by Mux with the complementary public key. Every video or thumbnail URL can have a unique signed token that can be used to authorize the request.

### Digital Rights Management (DRM)

For additional protection, Mux supports industry-standard DRM technologies. Mux uses Google Widevine, Microsoft PlayReady, and Apple FairPlay to provide an extra layer of content security. DRM requires the use of Signed URLs, and when combined with Domain and User-Agent restrictions, can provide very strong content protection, up to and including security levels that satisfy the requirements of Hollywood studios.

DRM encrypts your video files and only allows authorized players to decrypt them during playback. This prevents "right-click, save" theft and blocks most screen recording software and satisfies the legal requirements of most content studios.

To use DRM with Mux, you need to complete an onboarding process:

1. Request FairPlay certificate for Apple devices (requires Apple approval)
2. Mux handles Widevine and PlayReady certificates for you
3. Once enabled, you receive a DRM configuration ID
4. When creating assets, specify the DRM configuration
5. Generate both playback and license tokens for playback

## Video Ingestion & Processing

### Flexible Upload Options

Mux supports multiple ingest methods:

1. **URL-based ingestion**: Provide a URL to any web-accessible video file
2. **Direct upload**: Upload files directly from client applications using authenticated upload URLs
3. **Live RTMP/SRT streams**: Broadcast live content via RTMP (Real-Time Messaging Protocol) or SRT (Secure Reliable Transport)

Direct Uploads allow you to simplify your workflow by providing an authenticated upload URL to your client applications so content can be uploaded directly to Mux without needing any intermediary steps, like having your file stored online somewhere else first.

### Intelligent Encoding

Mux uses AI-powered per-title encoding that analyzes each video and generates an optimal bitrate ladder automatically. Instead of using a static encoding ladder that wastes bandwidth on simple videos and under-serves complex ones, Mux analyzes content characteristics and encodes accordingly.

Videos are encoded while the first viewers watch them, making them available to watch in just a few seconds after upload. Mux is the first video streaming platform that doesn't make users wait for transcoding, offering the fastest video publishing possible.

## Player Options & Customization

Mux offers multiple player choices:

### Mux Player

Mux Player is a comprehensive player with CSS parts allowing you to style each part individually with selectors, making it a powerful API for customization. Available for web (HTML/React), iOS, and Android. The player includes built-in support for captions, audio tracks, DRM, and integrates seamlessly with Mux Data for analytics.

### Framework Agnostic

Mux offers player-agnostic delivery, allowing you to use any HLS player of your choice. This means you could use Video.js, HLS.js, or any standards-compliant player that supports HLS (HTTP Live Streaming).

---

## Mux Data: Analytics & Quality of Experience (QoE)

Mux Data is a real-time analytics system included with Mux Video. Mux Data is included with Mux Video delivery, automatically tracking QoE metrics: startup time, rebuffering, errors, and engagement.

Key metrics tracked:

- **Startup Time**: How long before playback begins
- **Rebuffer Ratio**: Percentage of time spent buffering
- **Errors**: Playback failures and their causes
- **Engagement**: Watch time, viewer drop-off, seek patterns
- **Video Quality**: Resolution, bitrate, frame rate
- **Device & Network**: Browser, OS, connection type, CDN

Mux provides official SDKs for several languages that handle authentication and make it easier to work with the API, including JavaScript/TypeScript, Go, Python, Ruby, and Elixir.

## Features Summary

### Content Management
- Auto-generated thumbnails and GIFs
- Storyboards (timeline preview collages)
- Metadata support (title, description, custom fields)
- Watermarking
- Multiple audio tracks
- Static MP4 renditions for offline editing

### Playback Features
- Adaptive bitrate streaming (HLS)
- 4K support
- Offline playback capability
- Autoplay control
- Playback speed control
- Keyboard shortcuts
- Picture-in-picture

### Captions & Accessibility
AI-powered transcription and captioning makes content accessible and searchable. Mux offers free auto-generated captions for VOD in 20+ languages. You can also upload manual captions.

### Live Streaming
- Mux supports RTMP, RTMPS (secure), and SRT for live streaming, plus URL-based and direct upload for VOD. Mux offers standard, reduced, and low-latency modes configurable per live stream
- Low-latency HLS (LL-HLS) support with 3-5 second latency
- Automatic recording of live streams as VOD assets
- Simulcasting to third-party platforms

### Security Features
- Signed playback URLs with JWT
- DRM (Widevine, FairPlay, PlayReady)
- Domain restrictions (referrer validation)
- User-Agent restrictions
- Geographic restrictions
- Playback token expiration

## Webhooks & Event Notifications

Instead of polling the API to check asset status, use webhooks to be notified when an asset is ready. Mux can notify your application when:

- Asset ingestion starts/completes
- Asset becomes ready for playback
- Live stream begins/ends
- Errors occur
- Playback events (for analytics)

Each webhook request includes a signature so you can verify it came from Mux.

## SDKs & Developer Experience

The Node.js/TypeScript SDK provides convenient access to the Mux REST API from server-side applications. The library is fully typed for convenient access to the documented API. Official SDKs also exist for Elixir, Go, Python, and Ruby.

For your Golang backend, you'd use the Mux Go SDK to:

1. Create video assets
2. Generate signing keys
3. Create and manage playback IDs
4. Set up playback restrictions
5. Generate JWT tokens for playback

## Pricing Model

Mux uses a usage-based pricing model:

- **Encoding**: Charged per minute of input video duration
- **Storage**: Charged per GB per month (cold storage discounts available)
- **Delivery**: Charged per GB delivered to viewers
- **DRM**: $100/month minimum + $0.003 per license

There's a generous free tier for testing, and pay-as-you-go billing with optional prepaid credit plans for predictable costs.
